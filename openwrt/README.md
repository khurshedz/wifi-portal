# Портал на Xiaomi Mi Router 3A (OpenWrt): работает и без интернета

```
TezTez ─(кабель/через Кинетик)─► WAN  Mi Router 3A  Wi-Fi «Assalom Wi-Fi» ─► гости (192.168.2.x)
                                      │  uhttpd: страница + кеш + CGI
                                      └─ LAN-порт ─► комп (админ, 192.168.1.1)
```

* Пока интернет есть, роутер раз в час (HH:01) забирает с Render всё: страницу, данные и 7 фото.
  Каждые 5 мин он пингует Render, чтобы тот не засыпал, и отправляет накопленные сообщения.
* Когда интернета нет, гости видят последнюю копию с плашкой «📴 Нет интернета, данные на …».
* «💬 Админу»: при наличии интернета сообщение уходит в Telegram, как сейчас.
  Без интернета оно встаёт в очередь на роутере (до 500) и уходит, когда связь вернётся.
* «👥 Общий чат»: гости переписываются друг с другом. Сообщения хранятся только на роутере, интернет не нужен.
  Последние 200 сообщений держатся в памяти и пропадают при перезагрузке.
* Раз в сутки копия страницы пишется на флеш (`/root/portal-snapshot.tgz`).
  Если роутер перезагрузится без интернета, страница всё равно откроется.
* Любой адрес, который гость набирает по http, ведёт на страницу: DNS гостей отвечает 192.168.2.1 на всё.
  HTTPS-адреса сразу выдают ошибку, а не висят. Телефоны сами показывают «Войти в сеть».

## 1. Что купить
* Xiaomi Mi Router 3A (R3A): MT7628, 64 МБ RAM, 16 МБ флеш. OpenWrt называет его `xiaomi_miwifi-3a`.
* **Блок питания 12V 1A, штекер 5.5×2.1** (у продавца его нет).
* Кабель LAN: один для компа, второй для интернета.

## 2. Прошивка OpenWrt (по кабелю с компа, с Claude по шагам)
1. Сбросить роутер, пройти мастер Xiaomi, задать пароль.
2. Получить SSH через [OpenWRTInvasion](https://github.com/acecilia/OpenWRTInvasion). Нужна заводская прошивка с уязвимостью; если версия новее, сначала откатить.
3. **Сделать бэкап** всех `mtd` разделов (`dd if=/dev/mtdX`) и забрать их на комп.
4. Записать `openwrt-…-ramips-mt76x8-xiaomi_miwifi-3a-squashfs-sysupgrade.bin`. Брать актуальную стабильную версию с downloads.openwrt.org и сверяться со страницей устройства в OpenWrt ToH.
5. Зайти на http://192.168.1.1 и сразу задать пароль root.

> OpenWrt помечает 8/64 и 16/64-устройства как «слабые». Для нашей задачи (статика и shell-скрипты, без LuCI-плагинов) этого хватает.

## 3. Установка портала
С компа, роутер подключён по кабелю:
```sh
cd ~/PycharmProjects/captive_portal/openwrt
scp -O -r files/* root@192.168.1.1:/
scp -O setup.sh root@192.168.1.1:/tmp/
ssh root@192.168.1.1 'sh /tmp/setup.sh'      # роутер сам перезагрузится
```
Для `opkg install curl ca-bundle` нужен интернет: WAN-порт роутера должен быть уже подключён.

## 4. Проверка
* `ssh root@192.168.1.1 'portal-sync; ls /tmp/portal'` должно показать `sync ok`, index.html, info.json и media/.
* С телефона подключиться к «Assalom Wi-Fi»: должно появиться «Войти в сеть» и открыться страница.
* Выдернуть WAN, подождать 5 минут, обновить страницу: появится плашка 📴, общий чат работает.

## Файлы
| Файл | Что делает |
|---|---|
| `files/usr/bin/portal-sync` | синхронизация с Render, пинг, отправка очереди, снапшот на флеш |
| `files/usr/share/portal/portal.cgi` | `/cgi-bin/portal/api/*`: прокси к Render, офлайн-кеш, очередь, общий чат, `/media/<id>` |
| `setup.sh` | гостевая сеть, Wi-Fi, отдельный DNS для гостей, файрвол, uhttpd, cron |

Страница та же, что на Render. На роутере в `<html>` подставляется `data-api="/cgi-bin/portal"`,
по нему JS понимает, куда слать запросы, и показывает вкладку «Общий чат».

Проверено на компе (busybox + тестовый CGI-раннер): синхронизация, кеш, офлайн-плашка, очередь
и её отправка, общий чат (экранирование, антифлуд, CSRF), скачивание фото.
На самом роутере ещё **не проверено**: uhttpd, dnsmasq, файрвол и `jsonfilter` будем проверять после прошивки.
